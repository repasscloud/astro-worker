# Non-iOS distribution qualification

Astro Worker uses the owner's approved AGPL-3.0 distribution model. Review the exact candidate and channel terms together. Keep every applicable copyright and licence notice, preserve recipients' rights to modify and redistribute, and make the corresponding source for that exact artifact available at no charge. Assess installation-information requirements under the circumstances of the distribution. A project archive alone does not establish that all corresponding source requirements have been satisfied. The Flutter SDK, resolved dependencies, platform resources, and build tooling need to be accounted for. [AGPL-3.0 text](https://www.gnu.org/licenses/agpl-3.0.en.html)

| Channel | Build and distribution evidence to collect | Outstanding gate |
| --- | --- | --- |
| [Google Play](https://github.com/repasscloud/astro-worker/issues/29) | App bundle signed with the designated upload key, Play delivery APK certificate fingerprints, source link, privacy disclosure, and an offline install and upgrade on a representative device. | Verify the actual Play agreement, licensed-user terms, and Play protection configuration under the publishing account. |
| [Mac App Store](https://github.com/repasscloud/astro-worker/issues/31) | Store-signed macOS bundle and WidgetKit extension, matching App Group provisioning, displayed licence, and offline installation. | Evaluate the signed schedules, the user's effective EULA, and any store or receipt restrictions against the AGPL. |
| [Microsoft Store](https://github.com/repasscloud/astro-worker/issues/32) | Choose a Win32 installer or an MSIX with identity for Widgets Board. Validate the resulting package and the published licence and source links. | Verify effective end-user terms, optional licensing or receipt controls, and installation on Windows 11 under the Partner Center setup. |
| [Direct desktop](https://github.com/repasscloud/astro-worker/issues/33) | Verify Developer ID signatures and notarisation on macOS, Windows publisher signatures and installer behaviour, and that modified self-builds can run using their own identities. | Production signing credentials and clean-machine install and upgrade evidence. |
| [GitHub Releases](https://github.com/repasscloud/astro-worker/issues/34) | Stage a tagged revision with the artifact, licence notices, checksums, matching source and build instructions. Check anonymous downloads and a self-build without any paid account. | Publish and verify a specific release only after its signed artifacts and source are cleared. |
| [Public web](https://github.com/repasscloud/astro-worker/issues/35) | Deploy a clean versioned build under HTTPS, link the matching source prominently, and test installability, offline reload and rollback on the deployed origin. | Choose and verify the production host, deployment headers, supported browsers, and public source link. |

Play App Signing distinguishes the upload certificate from the certificate on Google-delivered APKs. Verify delivered builds separately. [Play App Signing documentation](https://support.google.com/googleplay/android-developer/answer/9842756)

macOS Developer ID distribution and Mac App Store distribution have separate signing paths. A custom store EULA, where accepted, is one input to the channel review. Review the applicable Apple agreement and schedules. [Apple Developer agreement](https://developer.apple.com/support/terms/apple-developer-program-license-agreement/), [Paid Applications schedules](https://developer.apple.com/support/downloads/terms/schedules/Schedule-2-and-3-English.pdf), [Developer ID signing](https://developer.apple.com/developer-id/)

Microsoft documents both MSI/EXE and MSIX submissions. The packaged native Windows widget path uses MSIX identity. [Windows distribution options](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/choose-distribution-path), [Store policies](https://learn.microsoft.com/en-us/windows/apps/publish/store-policies)

GitHub can link named release assets and provide a commit archive. Keep the release records bound to an immutable commit and verify the complete source required by the artifact. [GitHub release assets](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases)
