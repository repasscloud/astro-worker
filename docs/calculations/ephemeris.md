# Ephemeris decision

Astronomia 1.1.1 is the initial replaceable engine. It is a recent MIT-licensed pure-Dart port with no runtime package dependencies or platform binaries. VSOP87 coefficients ship as Dart constants. One provider serves native and browser and does not download additional ephemeris resources. Independent accuracy qualification and representative performance and size benchmarks are tracked separately. GeoEngine's Astronomy Engine port was evaluated locally and its umbrella package added 38 transitive additions, including database and geospatial tooling. Hevelius is Apache-2.0 and pure Dart, with an external JPL SPK resource lifecycle to qualify. [Astronomia](https://pub.dev/packages/astronomia/versions/1.1.1), [GeoEngine](https://pub.dev/packages/geoengine), [Hevelius](https://pub.dev/documentation/hevelius_ephemeris/latest/)

Astrodienst offers Swiss Ephemeris under AGPL or a signed Professional licence. Astrodienst states the licence must be selected before distributing software containing Swiss Ephemeris or activating a public service using it. Free distribution does not establish an exemption. The upstream DE431 compressed resource set spans roughly 13,000 BCE to 17,000 CE overall. Actual coverage depends on the chosen files and body, and differs for Moshier and minor objects. The owner approved AGPL-3.0 for Astro Worker and Swiss Ephemeris in [issue #1](https://github.com/repasscloud/astro-worker/issues/1). Qualify the licence, provenance and corresponding source for each selected binding, binary and resource before distribution. [Astrodienst programming documentation](https://www.astro.com/swisseph-download/doc/swephprg.pdf), [source and files](https://github.com/aloistr/swisseph)

The actively published `sweph` binding documents native FFI and browser Emscripten Wasm through `universal_ffi`, including both Dart browser compilers. Bundled planet, Moon and asteroid file coverage is described as 1800–2400. Maintainer-authored parts have a conditional LGPL option for eligible Professional licensees. Astrodienst's source, files and derived binaries still follow its agreement. Browser distribution must cover the delivered Wasm, data and notice or source requirements. Native distribution must account for every ABI and signed store package. [Binding documentation](https://pub.dev/packages/sweph)

For the Swiss Ephemeris evaluation, use versioned checksummed file bundles, validate requested ranges and refuse unintentional fallback when files are missing. Store small, approved native assets in platform bundles and larger optional resources in versioned app-private storage. Cache approved browser assets under the service-worker version. Swiss APIs expose process-global configuration, so investigate isolating or serialising access, and measure package size and search latency on each platform before adoption. [Tracking decision](https://github.com/repasscloud/astro-worker/issues/1)

The [Swiss qualification tools](../../tools/swiss_probe/README.md) pin the pub archive digest, compiled C source and headers, planetary, lunar and minor-body files, and Wasm digest for `sweph 4.1.0+2.10.3`. A macOS arm64 probe and an Android API 35 arm64 emulator accepted the expected Swiss flag for the Sun, Moon, Pluto, Chiron, and both nodes. Mac native and Node WebAssembly results agreed within 0.000000001° in the sample grid. With the lunar file absent, both returned the Moshier fallback flag. The raw probes reject that result.

The native test library was about 581 KB, the provided Wasm 466 KB, and the three data files about 2.0 MB. The warmed isolated Moon loop measured roughly 88,000 calls/s natively and 100,000 calls/s in Node on the Apple M2 Pro host. Lunar checks in 1801 and 2399 used the pinned Swiss file. These are raw-engine measurements. Flutter integration, per-device performance, and exact corresponding source for any distributed binaries remain separate checks.

The Windows Server 2025 probe also passed the strict flags and coverage checks. Offline Playwright Chromium 158, Firefox 159, and WebKit 27.2 instantiated the checksummed Wasm and loaded the three validated data files into its memory filesystem. The 18 longitude samples agreed with native macOS to within 0.00000000001°. All three browsers returned flag 260 with the lunar file absent, compared with the required 258. [Windows run](https://github.com/repasscloud/astro-worker/actions/runs/45480181627)

The pinned binding's public `swe_calc_ut` wrapper accepts requested flags and returns coordinates, discarding successful native result flags. The raw API exposes the actual flags. A production provider must preserve and check them to distinguish a Swiss result from a silent fallback, in addition to verifying the files before loading. [Pinned binding source](https://github.com/vm75/sweph.dart)
